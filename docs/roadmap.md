# Roadmap

Three milestones, each with an exit test that a reviewer can run. A milestone is done only when its exit test passes in CI. The commands below are the targets: the scripts and flags they name are built as part of each milestone, and none of them exists yet except `personal_ai.demo`, `scripts/eval_retrieval.py` and the manual `scripts/evaluate_agent.py`. No number appears in the README unless a command in this repository produces it.

## Milestone 1: Measured retrieval and answer quality

**Why:** the platform publishes no quality numbers yet. The evaluation harness (`src/personal_ai/retrieval_evaluation.py`) exists; it has no benchmark behind it.

**Scope**

* A synthetic corpus and a question set of 50 to 100 questions with labelled relevant chunks, committed under `tests/fixtures/synthetic/eval/`.
* Retrieval comparison: BM25, embeddings and hybrid RRF, scored with recall@5 and MRR.
* Citation correctness: the share of answers whose cited evidence ids support the answer, with a human-labelled subset to check the scorer.
* Latency: p50 and p95 per backend, reported with the named model and hardware.
* A results table at the top of the README, generated by a script, never typed by hand.

**Status:** built: retrieval comparison with recall@5 and MRR@5, evidence support@5 (do the cited chunks contain the facts an answer needs), a scorer check against labelled citations, a latency table, thresholds, and the generated README tables with the `--check` gate. Not built: faithfulness scoring of generated answers, which needs a model; a person's review of the citation labels, which are AI-drafted; and a run with a real embedding model. The semantic backend uses an offline n-gram vectoriser, so the paraphrase numbers say little about semantic search until that run exists. Latency is machine-dependent, so `--check` requires its README block but does not compare it.

**Exit test**

```bash
uv run python scripts/eval_retrieval.py --check
```

The command regenerates the table, compares it with the README, and fails on any difference. CI runs it. Quality thresholds are set from the first measured run and committed next to the question set.

## Milestone 2: Governance you can watch, and an agent evaluation gate

**Why:** the human-approval boundary is the main idea of the project. It is tested, but it is not yet easy to see or to regress-check at the agent level.

**Scope**

* A 30-second governance demo GIF: the agent proposes a network action, the policy blocks it, a human approves, the audit log records the decision. It replaces the placeholder in the README.
* An agent evaluation harness over synthetic tasks: tool-call correctness, refusal of disallowed actions, and no action without approval.
* A regression gate in CI that fails when any of those scores drop below the committed baseline.

**Exit test**

```bash
uv run python scripts/evaluate_agent.py --synthetic --check
```

The command runs the synthetic task set offline with a scripted model, writes the scores, and fails if tool-call correctness or refusal behaviour falls below the baseline. `tests/test_demo.py` keeps passing.

## Milestone 3: Air-gapped deployment profile

**Why:** the platform is local-first by design. This milestone proves it under a no-egress constraint instead of claiming it.

**Scope**

* An offline model registry: models are loaded from a local directory, never pulled at runtime.
* A software bill of materials for every release, and a signed container image.
* A no-egress test: the container starts and answers a retrieval request with all network access disabled.
* Optional and generic: document-level labels with retrieval filtered by label and an audit trail, using unclassified synthetic labels only.

**Exit test**

```bash
docker run --rm --network none personal-ai:latest python -m personal_ai.demo
```

The demo completes with zero network calls. A CI job runs this command and also verifies that the SBOM and image signature exist for the tagged build.
